# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Timezone-naive string manipulation (`punch_in.replace(...)` ignores IST), fails for overnight shifts, and uses incorrect integer floor comparison (`minutes > 10`), causing punch-ins 10m 30s late to return 0 instead of 10 minutes late (Rule R2). | Punch-in at 09:40:01 for a 09:30 shift returned 0 late minutes instead of 10. | Converted `punch_in` to IST, combined shift start with attendance date in IST, checked `diff_seconds > 600`, and calculated `int(diff_seconds // 60)`. |
| 2 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round(..., 2)` which performs banker's rounding (round half to even) instead of round half-up required by R4 and R8. | Work hours calculation ending in exact half-way fractions (e.g., .005) rounded down to even digits instead of rounding up. | Used `Decimal` with `ROUND_HALF_UP` quantized to 2 decimal places. |
| 3 | `compute_overtime` (lines 44-47) | Did not enforce the 30-minute minimum threshold (R3) and did not handle overnight shifts where `shift_end` falls on the next calendar day. | Punch-out 5 minutes after shift end returned 5 overtime minutes instead of 0; overnight shift overtime was calculated against the start day's morning. | Checked whether `shift_end <= shift_start` to increment the shift end date by 1 day, and enforced `diff_seconds >= 1800` before calculating minutes. |
| 4 | `health` (lines 72-74) | Static response returning `{"status": "ok"}` without pinging MongoDB or returning HTTP 503 on failure. | Stopping MongoDB still resulted in HTTP 200 OK from `/health`. | Executed `client.admin.command("ping")` and raised `HTTPException(503, "Database unavailable")` on failure. |
| 5 | `create_employee` (lines 78-85) | Check-then-insert race condition (`find_one` then `insert_one`), accepted equal `shift_start` and `shift_end`, used naive local `datetime.now()`, and returned raw doc leaking `_id`. | Concurrent requests with identical `emp_code` created duplicates; sending `shift_start == shift_end` returned 201; timestamp was returned as local datetime string. | Relied on MongoDB unique index on `emp_code` catching `DuplicateKeyError` -> 409, validated `shift_start != shift_end` (422), stored UTC datetime, and returned epoch ms integer without `_id`. |
| 6 | `list_employees` (lines 88-96) | Off-by-one pagination bug (`skip = page * page_size` skips page 1 completely), `total` ignored the `department` query filter, and items were not sorted by `emp_code` ascending. | Requesting `page=1` returned page 2 results; `total` always reported total collection size regardless of filter; results were unsorted. | Changed skip to `(page - 1) * page_size`, passed query filter `q` into `count_documents(q)`, and added `.sort([("emp_code", 1)])`. |
| 7 | `punch_in` (lines 99-122) | Check-then-insert race condition; crashed with 500 `KeyError` if employee did not exist; calculated attendance date using local `ts.date()` ignoring IST and overnight shifts (R1); did not truncate microseconds to whole seconds; injected non-contract `"id"` field. | Concurrent punch-ins created duplicates; unknown employee threw 500; overnight punch-in at 05:00 IST was marked on the wrong date; response contained unwanted `id` field. | Checked employee existence (404); truncated instant to whole seconds; calculated IST attendance date with overnight shift rule; enforced unique index `(emp_code, date)` catching `DuplicateKeyError` -> 409; returned schema-compliant `AttendanceRecord`. |
| 8 | `list_attendance` (lines 124-150) | Loaded entire collection into memory with `list(db.attendance_logs.find(q))` and sorted/sliced in Python; did not validate `date_from > date_to`; returned raw BSON dates and injected `"id"` field. | High latency and OOM on 100k records; `date_from > date_to` returned 200 with empty list instead of 422; response contained BSON datetimes and `id`. | Validated `date_from <= date_to` (422); delegated sorting and pagination to MongoDB (`.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`); converted timestamps to epoch ms. |
| 9 | Request input validation (lines 53-68) | Allowed seconds-looking timestamps (< 100000000000), floats, and strings for epoch millisecond fields; allowed invalid status values in punch-in. | Submitting `{"punched_at": 1783310280}` or `{"punched_at": "1783310280000"}` or invalid statuses was accepted instead of rejected with 422. | Added strict Pydantic validation using `Annotated[int, Field(strict=True, ge=100000000000, le=4102444800000)]` and Literal status types. |
| 10 | Startup index creation | No indexes were created at startup, leaving only the default `_id` index. | Database operations performed `COLLSCAN`, failing performance and explain requirements on large datasets. | Added lifespan handler creating unique and compound indexes idempotently at startup. |

### Examined and decided NOT a defect:
1. **Use of `python-dotenv` / `load_dotenv()`**: Loading `.env` is explicitly permitted by `PROBLEM_STATEMENT.docx` section 4 as long as environment variables take priority.
2. **FastAPI app title and version**: Metadata matches the OpenAPI definition.
3. **Storing UTC BSON datetimes in MongoDB**: Storing BSON datetimes in MongoDB and converting to/from epoch milliseconds at the API boundary matches `DATA_MODEL.md` requirements.
